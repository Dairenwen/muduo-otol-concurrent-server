HTTP Lab/download.html
RELEASE / 08

准备好一个可使用的发布包。

发布目录包含空入口程序、静态库、带版本的动态库、公共头文件，以及 CMake 导入配置。

产物布局

release/
  server
  lib/libserver.a
  lib/libserver.so → libserver.so.0
  lib/libserver.so.0 → libserver.so.0.1.0
  lib/libserver.so.0.1.0
  include/server/
  lib/cmake/server/
  wwwroot/

server 是正式启动入口；测试程序另外提供手动模式。默认端口 8080，可通过命令行覆盖。

作为 CMake 依赖

find_package(server CONFIG REQUIRED)
target_link_libraries(your_app PRIVATE server::server)
# 动态库：server::server_shared

设置 CMAKE_PREFIX_PATH 指向解压后的发布目录即可查找。二进制需使用匹配的 Linux 架构与运行环境。

PACKAGE IT ONCE

生成可上传的归档。

cmake --install build --prefix "$PWD/release"
cpack --config build/CPackConfig.cmake

归档包含 server、头文件、动静态库、CMake 导入配置、网页与许可证。文件名包含项目版本、Linux 与 CPU 架构。

为什么有多个 .so 名称？

libserver.so 和 libserver.so.0 都是指向 libserver.so.0.1.0 的版本软链接。实际动态库只有一份，静态库 libserver.a 是另一种链接形式。相同版本的构建覆盖同名产物。

选择一种链接方式。

静态链接

使用 server::server。库代码在链接时合入应用，部署时无需携带 libserver.so。

动态链接

使用 server::server_shared。应用运行时需要匹配的共享库与动态加载路径。

cmake -S your-project -B your-build -DCMAKE_PREFIX_PATH=/path/to/release

当前代码依赖 Linux API；发布包不是 macOS 或 Windows 可执行包。测试结果见 release 中的审查说明。
