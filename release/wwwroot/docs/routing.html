ROUTING / 04

路径清晰，响应才清晰。

所有页面链接与资源路径都从静态根目录出发，不依赖当前浏览器所在的目录。

静态优先

GET 与 HEAD 先查找静态资源；存在的目录会读取其中的 index.html。文件不存在时再匹配动态处理函数。

/docs/ → /docs/index.html

方法分开注册

测试入口分别注册 GET、POST、PUT 和 DELETE 接口；HEAD 复用 GET 的响应头，省略正文。

/api/items/42

动态接口清单

方法路径用途
GET / HEAD/api/status状态 JSON
GET/api/query?name=Lin查询参数解码
POST/api/items正文长度检查
PUT / DELETE/api/items/42正则路径匹配

路径穿越请求会在解析阶段被拒绝。请保留原始路径进行测试，避免客户端先把 ../ 规范化。

READ THE RESPONSE

响应头透露了什么？

字段检查方式
Content-TypeHTML 为 text/html；公共样式为 text/css；API 状态为 application/json。
Content-Length按字节计算，必须与 GET 正文的实际长度一致。
Connectionclose 后连接结束；keep-alive 可以继续发送新请求。
Location/redirect 返回 302，目标为 /index.html。

用一组请求比较路径。

curl -i http://127.0.0.1:8080/docs/
curl -i http://127.0.0.1:8080/docs/index.html
curl -i http://127.0.0.1:8080/index%2Ehtml
curl -i http://127.0.0.1:8080/missing-page

前三项读取真实文件，最后一项返回 404。Linux 路径区分大小写，所以 /INDEX.html 与 /index.html 是不同资源。

查询参数会改变静态文件路径吗？

/index.html?theme=light 仍应读取 index.html。查询字符串由请求解析器单独处理，不是文件名的一部分。
