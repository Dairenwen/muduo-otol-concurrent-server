先检查最容易忽略的地方。

目录、端口与响应边界，是静态服务器测试中最常见的三个起点。

常见问题

怎样使用正式入口启动网页？

运行 ./release/server，或使用 ./release/server --port 9090 指定端口。测试程序仍提供 HTTP_TEST_SERVE=1 手动模式。

从不同目录运行会找不到 wwwroot 吗？

CMake 为测试程序指定绝对资源路径。移动资源后，可以使用 HTTP_TEST_WWWROOT 环境变量覆盖。

为什么 /404.html 返回 200？

它是存在的静态示例页面。请求不存在的 /missing-page 才返回 HTTP 404；当前服务器默认使用纯文本错误正文。

HEAD 应该返回 HTML 吗？

HEAD 返回与 GET 对应的响应头和正文长度，但不会发送正文。

页面里出现样式或脚本 404 怎么办？

确认资源根目录正确，并检查 /assets/style.css 与 /assets/app.js。本站所有资源链接都使用绝对站内路径。

QUICK REFERENCE

随手可用的命令。

./release/server --help
./release/server --port 9090 --threads 2
ctest --test-dir build --output-on-failure
curl -I http://127.0.0.1:9090/docs/
端口被占用时会发生什么？

启动失败并输出原因。选择不同的 --port，不要为了运行演示程序停止无关服务。

能否关闭工作线程？

--threads 0 使用主事件循环；默认使用 3 个工作线程。工作线程数应在启动前配置。

自动测试出现失败，应该怎么处理？

先保留失败用例与日志，按具体请求定位实现。不要把实际错误行为改成测试预期，也不要在未审查时修改未授权的源文件。
